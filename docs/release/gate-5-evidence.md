## Licence boundary

Lamplight code and documentation use Apache-2.0, declared by the root
`LICENSE`, package metadata, `NOTICE` and the default annotation in
`REUSE.toml`. `LICENSES/Apache-2.0.txt` provides the corresponding SPDX licence
text. Each future npm package carries byte-identical package-local copies of
the Apache licence and notice, enforced against the canonical root files.

The eight IBM Plex binary assets, their generated byte-identical copies and
their OFL text use the later, narrower OFL-1.1 annotation. The override names
font extensions and `OFL.txt` explicitly. It does not match
`lamplight-fonts.css`, which remains Lamplight code under Apache-2.0. `NOTICE`
states that the Apache licence does not replace or broaden the font licence.

`npm run gate5:licence` checks both licence texts, package metadata, annotation
order and exact font-copy hashes. Result: passed, with eight IBM Plex assets
classified under OFL-1.1.

## Security model and local controls

The root `SECURITY.md` defines the system, security scope, consumer, DOM,
supply-chain and distribution trust boundaries, enforceable invariants,
reportable findings, exclusions and current evidence limitations. The security
policy resolver selects this root policy for repository scope.

There is no invented email address or vulnerability URL. GitHub private
vulnerability reporting is the intended Gate 7 route only after a repository
exists and the feature is enabled and verified.

`npm run gate5:security` enforces:

- exact workflow names, full reviewed action SHAs and per-workflow permission
  maps;
- rejection of risky triggers, secret expressions, untrusted event expressions
  in shell commands and pre-Gate-7 release capabilities;
- schema and ecosystem coverage for Dependabot;
- lockfile version, exact direct development versions, npm-registry origins and
  SHA-512 integrity for resolved dependencies;
- an exact reviewed list of the three transitive development dependencies with
  install scripts: esbuild 0.28.2 and the two platform-only fsevents copies;
- no first-party runtime or optional dependencies and no first-party install,
  preparation or packing lifecycle script;
- no network-capable operation in the packaged browser and React JavaScript;
  and
- credential-like filenames and secret signatures across every Git commit,
  while emitting filenames rather than matched content.

The privacy scanner also covers current tracked and candidate files, generated
package surfaces, licences, workflows, repository controls and release
evidence. It continues to validate every author and committer identity in Git
history against the explicit public-safe allowlist.

Six Gate 5 regression tests pass. The negative cases prove rejection of a
floating action tag, excess contents permission, `pull_request_target`, a
secret expression and an npm publish command. A separate assertion prevents
the Astro-dependent full test suite being assigned to Node 20.
