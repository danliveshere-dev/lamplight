# Governance

Lamplight is a small maintainer-led open-source project. The maintainer sets its
scope, accepts releases and may decline work that would turn the design system
into an application framework or a consumer-specific theme.

## How decisions are made

Small fixes can proceed through a focused pull request. A new public token,
class, component, adapter, dependency, browser requirement or licence boundary
starts with an issue that states the use case, alternative, compatibility cost
and evidence plan. The maintainer records compatibility decisions in release
notes and migration guidance rather than relying on discussion history alone.

Accessibility and security findings are release blockers until independently
reviewed. A green automated check does not substitute for assistive-technology,
visual or maintainer-held acceptance when the change needs those judgements.

## Maintainer and contributor responsibilities

The maintainer owns package names, release timing, supported versions and the
security-reporting route. Contributors retain authorship of their commits under
the repository licence and are expected to use synthetic fixtures, protect
private information and keep changes within Lamplight's documented boundaries.

There is no promised response time or release cadence. Quiet periods do not
mean the project is abandoned. See the [support policy](SUPPORT.md) for where to take a report.
